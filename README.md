# 🕹️ Unity 팀 프로젝트 - Followers_Project_Survival

> **자원 수집, 전투, 건축, 생존, 환경 요소를 구현한 3D 액션 서바이벌 프로젝트**  
> Unity 엔진과 C#을 활용하여 Behavior Tree 기반 AI 시스템, 수집한 자원 기반 아이템 제작 및 건물 구축 시스템, 날씨와 환경에 영향받는 생존 스탯 시스템

## ✨ 구현 기능

### 1. 자원 수집 및 가공
- 필드에 생성된 자원 오브젝트로부터 자원을 캘 수 있음
- 제작대를 통해 수집한 자원을 가공하여 아이템을 제작할 수 있음

### 2. 식사와 수분 관리
- 플레이어의 스탯에 허기, 갈증 스탯을 추가
- 물을 먹거나 음식을 먹어 허기, 갈증 스탯을 회복

### 3. 건축 및 생존 기지 구축
- 제작대에서 자원을 소모해 집을 지을 수 있음

### 4. 적과의 전투
- 플레이어와 적의 공격 기능 구현을 통해 서로 데미지를 주고 받을 수 있음
- Behavior Tree 기반으로 AI를 구현하여 정찰, 추적, 공격을 자연스럽게 전환할 수 있도록 구현

### 5. 생존 관리 시스템
- 갈증, 허기 스탯이 시간이 지남에 따라 지속적으로 감소하게 구현
- 갈증, 허기 수치가 0이 되면 체력이 감소하도록 구현

### 6. 자원 리스폰
- 소환된 오브젝트 좌표를 저장하고 일정 거리 떨어진 위치에서만 새로운 오브젝트 소환가능하도록 로직 구현
- 자원 오브젝트 파괴 시 자동으로 리스폰되어 지속적인 자원 확보 가능

### 7. NPC와의 대화 기능
- NPC와 상호작용을 통해 대화 기능을 구현
- 대화 연출, 타이핑 연출

### 8. UI 애니메이션 추가
- DoTween 활용하여 UI 애니메이션 추가

### 9. 날씨와 환경 요소
- 날씨, 온도, 시간 등 여러 환경 요소의 변화에 따라 플레이어의 생존 스탯이 영향받도록 구현
- 온도에 따라 갈증과 허기 수치 감소량 추가 증가

### 10. 크래프팅 시스템
- 제작대를 통해 수집한 자원을 가지고 검, 곡괭이 등 아이템 제작 구현

## 🛠️ 트러블 슈팅 - 자원 및 NPC 스폰 시스템  

### 문제 상황
- 자원과 NPC가 동일 좌표에 스폰되는 문제가 발생했습니다.  
- 자원 오브젝트 위에 NPC/적이 겹쳐서 스폰되어 **자원 채집 불가, 이동 방해**가 발생했습니다.  

### 원인
- 자원 스폰 시 평면 좌표를 관리했지만, NPC 스폰은 별도의 좌표 관리가 없었습니다.  
- 그 결과 NPC가 자원 위치에 그대로 스폰되는 현상이 발생했습니다.  

### 해결 방법
- 스폰 순서를 변경하여 **NPC/적 먼저 스폰 → 좌표 저장 → 이후 자원 스폰 시 거리 체크 후 배치**하도록 수정했습니다.  
- 자원과 NPC 모두 동일한 좌표 리스트를 공유하여 **일정 거리 이상 떨어진 위치에서만 스폰**되도록 로직을 개선했습니다.  

### 결과
- 자원과 NPC가 겹쳐 스폰되는 문제가 해결되었습니다.  
- 플레이어가 자원에 접근할 수 있고, NPC와 자원이 정상적으로 상호작용할 수 있게 되었습니다.

## 🛠️ 트러블 슈팅 - Behavior Tree 기반 몬스터 행동 패턴  

### 문제 상황
- 몬스터의 공격 모션 도중 다른 조건(체력, 거리)이 바뀌면 **행동이 중단되고 다른 상태로 전환**되는 문제가 발생했습니다.  
- 그로 인해 **공격 애니메이션이 끊기고 부자연스러운 전투**가 연출되었습니다.  

### 원인
- 기존 상태머신은 `if-else` 조건으로만 제어하여, **행동 우선순위**와 **모션 중단 방지 로직**이 없었습니다.  

### 해결 방법
- Behavior Tree를 도입하여 몬스터 행동을 **노드 단위로 관리**했습니다.  
- 모션 도중에는 `Running` 상태를 반환하여 **중간에 Interrupt되지 않도록** 처리했습니다.  
- Selector 노드로 **우선순위(Death > Attack > Chase > Rest)**를 설정했습니다.  

### 결과
- 공격 모션이 끝까지 재생되며 전투가 자연스러워졌습니다.  
- 상황에 따라 우선순위가 보장되어 **실시간 반응형 AI**를 구현할 수 있었습니다.

## 🛠️ 트러블 슈팅 - 건축 구조 개선  

### 문제 상황
- 나무 집, 제작대 등 건축물마다 필요한 기능이 달라, 스크립트에 **중복된 코드가 많아졌습니다.**  
- 기능 확장 시 코드 유지보수가 어려워지는 문제가 발생했습니다.  

### 원인
- 건축 기능(수리, 상호작용, 제작 등)을 각각 개별 스크립트에 구현하려다 보니 **코드 재사용성이 낮았습니다.**  

### 해결 방법
- `BuildObject`라는 추상 클래스를 만들어 공통 기능을 상속받도록 구조를 개선했습니다.  
- 상호작용, 수리 등은 `IInteractable`, `IRepairable` 같은 **인터페이스**로 분리하여 필요할 때만 구현하도록 했습니다.  

### 결과
- 중복 코드를 줄이고, 새로운 건축물을 추가할 때 코드 재사용성이 높아졌습니다.  
- 유지보수와 확장이 쉬운 구조로 개선되었습니다.

## 🛠️ 트러블 슈팅 - 플레이어 애니메이션 상하체 분리  

### 문제 상황
- 이동 중 공격 애니메이션을 실행하면 **하체 애니메이션이 멈춰버리는 문제**가 발생했습니다.  
- 결과적으로 상체와 하체가 동시에 자연스럽게 동작하지 않았습니다.  
![AttackBefore](https://github.com/user-attachments/assets/700ed68c-ac3b-45b2-813d-f35dbbeae5d8)

### 원인
- 단일 애니메이션 레이어에서 상체와 하체를 동시에 제어하려고 하여, **공격 모션이 하체 이동 모션을 덮어써버렸습니다.**  

### 해결 방법
- 새로운 Upper Layer를 추가하고, `AvatarMask`를 사용하여 상체만 남기고 하체를 마스킹했습니다.  
- Upper Layer의 Weight를 1로 설정해 상체는 공격 모션, 하체는 이동 모션을 각각 재생할 수 있도록 했습니다.  

### 결과
- 플레이어가 이동하면서도 상체로 공격할 수 있어, **부드럽고 자연스러운 전투 애니메이션**이 가능해졌습니다.
